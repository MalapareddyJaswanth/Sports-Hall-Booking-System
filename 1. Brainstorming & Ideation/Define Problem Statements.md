# Define Problem Statements

This document outlines the core problem statements, target personas, and project scope for the **Sports Hall Booking System**.

## 1. Problem Statements

### Problem 1: Slot Conflict & Double Booking
*   **Statement**: Multiple users often request the same sports court at the same time, leading to scheduling conflicts and arguments when manual sheet records overlap.
*   **Impact**: Operational chaos, poor user satisfaction, and manual dispute resolution.

### Problem 2: Late Approvals and Manual Notifications
*   **Statement**: Approvals are handled via email threads or phone calls by coordinators, leading to delays and lack of confirmation.
*   **Impact**: Sports courts remain unutilized or students show up without confirmation.

### Problem 3: Idle / Expired Bookings
*   **Statement**: Slots are reserved but unused if coordinators forget to mark them as completed or release holds.
*   **Impact**: Reduced court utilization and lost booking opportunities for other students.

---

## 2. Target Personas
*   **Student (User)**: Needs quick self-service booking, real-time availability checks, and clear notification of status.
*   **Facility Coordinator (Approver)**: Needs an intuitive interface to manage, approve, or reject booking requests without manual email threads.
